# تقرير النواقص: كل برنامج في Nigafiy مقارنةً بالمنافسين

التاريخ: 2026-11-28. الفرع `phase-2-network-intelligence` عند `3bb46b0` (الإصدار 1.0.9).

**الطريقة:** قرأت `docs/roadmap/status.md` والـ README، وبحثت في الكود (API والـ Sensor والـ Agent وتطبيق أندرويد) عن كل ميزة. بعدين قارنت بالمنتجات اللي بتعمل نفس الشغل: Domotz وAuvik وFing (الشبكة)، وNinjaOne (إدارة الأجهزة)، وNextDNS وFirewalla (الحماية والرقابة)، وUptime Kuma (المراقبة).

**الخلاصة في سطرين:** عدد الميزات كبير وأكبر من أغلب المنافسين. المشكلة الأولى إن جزء كبير منها **متجرّبش على جهاز حقيقي** (اختبارات بس). المشكلة التانية إن فيه **ميزات أساسية عند كل المنافسين ومش موجودة عندنا خالص**، وأهمها: استهلاك الإنترنت لكل جهاز، وقياس سرعة الإنترنت، والبحث الآمن (SafeSearch)، وحدود وقت يومية، وتحديث البرامج الخارجية، وsyslog.

درجات الأولوية:
- 🔴 = ناقص أساسي، والعميل هيلاحظه فورًا
- 🟠 = مهم علشان المنتج يبان احترافي
- ⚪ = تحسين

---

## 1. Hub (الدخول والإعدادات والتحديثات والتثبيت)

**الموجود:** كلمات سر scrypt، وMFA بـ TOTP، وOIDC/SAML، وأدوار، وسجل تدقيق، وتحديثات موقّعة، وNSIS/MSI/MSIX، ونسخ احتياطي.

| الناقص | مين عنده | الأولوية |
|---|---|---|
| **توقيع كود حقيقي.** المثبّتات موقّعة بشهادة تجربة، والعميل محتاج يشغّل `Trust-Nigafiy.cmd`. أول حاجة أي عميل هيشوفها هي تحذير SmartScreen. | كل المنتجات التجارية | 🔴 |
| **خادم تحديثات فعلي.** التحديث التلقائي مقفول، ومفيش manifest منشور. | كل المنافسين | 🔴 (لو هتبيع) |
| قاعدة البيانات `embedded-postgres`، والوثائق نفسها بتقول إنها "للتطوير، والإنتاج محتاج PostgreSQL مُدار" | — | 🟠 |
| Passkeys / WebAuthn (مفيش أي كود لها) | NinjaOne وأغلب الـ SaaS | ⚪ |
| تقارير PDF مجدولة بالإيميل. التقرير الموجود "قابل للطباعة" بس، والتقرير الأسبوعي بيتبعت كنص في القنوات. | Domotz وAuvik وNinjaOne | 🟠 |
| ترخيص / تفعيل / فواتير (الوثائق بتقول "No billing") | كل المنتجات المدفوعة | 🟠 (لو هتبيع) |
| خدمة الـ engine كـ Windows service: الوثائق لسه بتقول "متجرّبتش كـ LocalSystem". محتاج تأكيد. | — | 🟠 |

## 2. Radar (اكتشاف الأجهزة)

**الموجود:** ICMP وARP وmDNS وSSDP وNetBIOS وDHCP passive وIPv6 وLLDP/CDP/MNDP، وخريطة شبكة، وIPAM.

| الناقص | مين عنده | الأولوية |
|---|---|---|
| **قاعدة بيانات تعرّف على الأجهزة بالموديل.** عندنا قواعد ثابتة بس، والموبايلات اللي MAC بتاعها عشوائي بتظهر "Phone / tablet — low confidence" ومن غير اسم. Fing بيعرف الماركة والموديل من قاعدة بيانات ضخمة. | Fing وDomotz | 🔴 |
| قوالب SNMP جاهزة حسب نوع الجهاز: حبر الطابعة، وبطارية الـ UPS، وهارد الـ NAS. البرنامج بيعرف إن الجهاز طابعة، بس مفيش مراقبة جاهزة ليها، والموجود OID يدوي بس. | Domotz وAuvik وPRTG | 🟠 |
| الخريطة اتجرّبت على حوالي 20 جهاز وهمي بس. محتاجة تجربة على مئات الأجهزة وعلى أكتر من subnet. | Auvik | 🟠 |
| IPv6 اتجرّب في اختبارات بس | — | ⚪ |

## 3. Watch (المراقبة والحوادث والتنبيهات)

**الموجود:** فحوص Ping وTCP وDNS وHTTP وTLS وSNMP OID، وحوادث، وNetwork Doctor، وTime Machine، وتنبيهات إيميل وTelegram وSlack وDiscord وntfy، وتصعيد.

| الناقص | مين عنده | الأولوية |
|---|---|---|
| **قياس سرعة الإنترنت المجدول، وتقرير أداء مزوّد الخدمة (ISP SLA).** مفيش أي speed test في الكود. | Fing وDomotz وFirewalla | 🔴 |
| **استهلاك الإنترنت لكل جهاز ("مين واكل النت").** مفيش NetFlow ولا sFlow ولا عدّاد bytes لكل جهاز. | Firewalla وAuvik | 🔴 |
| **Syslog receiver**: استقبال لوجات الراوتر والسويتش والفايروول والتنبيه منها | Auvik وPRTG | 🟠 |
| SNMP traps (لما الجهاز نفسه يبلّغ عن عطل) | Auvik وPRTG | 🟠 |
| فحص HTTP بكلمة في الصفحة أو JSON. الموجود حاليًا كود الحالة (status code) بس. | Uptime Kuma | 🟠 |
| فحص Push / heartbeat: الخدمة أو مهمة الـ cron هي اللي تبلّغ إنها شغالة | Uptime Kuma | ⚪ |
| صفحة حالة (status page) تتشارك مع الموظفين أو العملاء | Uptime Kuma | ⚪ |
| baselines تغيّر حدود التنبيه لوحدها. الوثائق بتقول إن متوسط 7 أيام بيتستخدم في الكلام بس. | Auvik وPRTG | 🟠 |
| تنبيه بالـ SMS أو WhatsApp أو مكالمة | Domotz وPagerDuty | ⚪ |
| **محصلش أي عطل حقيقي** يجرّب الحوادث والـ Doctor، وTelegram/Slack/Discord/ntfy متجرّبوش على الخدمة الحقيقية. أسهل حل: افصل الراوتر عن الإنترنت 5 دقايق وشوف النتيجة. | — | 🔴 (تجربة، مش كود) |

## 4. Guard (الحماية والتحكم في الراوتر والـ DNS)

**الموجود:** فلتر DNS بفئات، وإيقاف مؤقت، ومواعيد نوم، و16 تعريف راوتر، والتحكم في منافذ السويتش، وفحوص أمان، ونسخ احتياطي للإعدادات ومقارنتها واسترجاعها.

| الناقص | مين عنده | الأولوية |
|---|---|---|
| **SafeSearch إجباري (Google/Bing) وYouTube Restricted Mode.** مفيش أي كود له، مع إن تنفيذه في فلتر DNS سهل نسبيًا: بيرجّع CNAME لـ `forcesafesearch.google.com` و`restrict.youtube.com`. | NextDNS وFirewalla | 🔴 |
| **حد وقت يومي**: مثلًا "يوتيوب ساعة في اليوم" أو "الطفل ده 3 ساعات نت". الموجود مواعيد وإيقاف مؤقت بس. | Firewalla | 🔴 |
| فلتر DNS **متجرّبش على أجهزة حقيقية في الشبكة**، اتجرّب على loopback بس | — | 🔴 (تجربة) |
| 15 من الـ 16 تعريف راوتر **متجرّبوش على راوتر حقيقي** (Zyxel بس اتجرّب) | — | 🟠 (كل عميل عنده راوتر مختلف) |
| فحص ثغرات للراوتر والأجهزة: firmware قديم أو CVE معروف أو باسورد افتراضي. الموجود فحص UPnP بس. | Fing وFirewalla | 🟠 |
| كشف تسلل أو اتصال بسيرفرات خبيثة (threat intel) | Firewalla | ⚪ |
| النسخ الاحتياطي والاسترجاع اتجرّبوا على محاكاة بس | Auvik | 🟠 (تجربة) |

## 5. Fleet (أجهزة الكمبيوتر)

**الموجود:** تحكم عن بعد WebRTC/H.264، وملفات، وshell، وسكربتات، وjobs، وتحديثات الويندوز ولينكس وماك، وسياسات وصول، وتسجيل الجلسات، وQuick Support، وCompliance.

| الناقص | مين عنده | الأولوية |
|---|---|---|
| **تحديث البرامج الخارجية**: Chrome وZoom وAdobe و7-Zip وغيرها. الموجود تحديثات نظام التشغيل، والتثبيت بـ winget بالطلب. أي RMM محترف بيعمل الحتة دي تلقائي وبموافقات. | NinjaOne وAction1 | 🔴 |
| **ربط البرامج المثبّتة بثغرات CVE معروفة** (Vulnerability management) | NinjaOne وAction1 | 🟠 |
| تذاكر دعم (helpdesk/ticketing). "Request help" موجود، بس مفيش تذكرة ليها حالة ومسؤول ومدة SLA. | NinjaOne وAtera | 🟠 |
| Agent لينكس وماك **متشغّلش ولا مرة على جهاز حقيقي** (cross-compile بس) | — | 🟠 (تجربة) |
| جلسة بين جهازين حقيقيين مختلفين في شبكة واحدة: الوثائق بتقول متعملتش. محتاج تأكيد إنها اتعملت بعد 1.0.7. | — | 🟠 |
| TURN relay مش موجود (قرارك)، فالتحكم من بره البيت بيعتمد على Tailscale | AnyDesk وRustDesk | ⚪ (مقبول طالما Tailscale شغال) |
| تحكم من الموبايل للموبايل بـ WebRTC: الموبايل بيبعت WebSocket بحد أقصى 15 fps | AnyDesk | ⚪ |

## 6. Android Agent (الموبايلات)

**الموجود:** تسجيل بالـ QR، وجرد، وCompliance، وقفل الجهاز، وسياسة الباسورد، والكاميرا، وتثبيت APK، ومسح الجهاز، وعرض الشاشة والتحكم فيها.

| الناقص (مفيش له أي كود) | مين عنده | الأولوية |
|---|---|---|
| **موقع الجهاز / وضع الفقدان (Lost mode)** | كل MDM (Intune وNinjaOne MDM وHexnode) | 🔴 |
| وضع Kiosk / Lock Task (الجهاز يشغّل تطبيق واحد بس) | كل MDM | 🟠 |
| إخفاء تطبيقات أو منعها أو منع إلغاء تثبيتها | كل MDM | 🟠 |
| دفع إعدادات Wi-Fi للموبايل | كل MDM | ⚪ |
| سياسة تحديث النظام (`setSystemUpdatePolicy`) | كل MDM | ⚪ |
| iOS مش مدعوم خالص (محتاج Apple MDM و APNs) | كل MDM | ⚪ (قرار كبير) |

## ترتيبي المقترح

1. **تجارب حقيقية، من غير كود:** افصل النت علشان تشوف الحوادث والـ Doctor، ووجّه موبايل واحد على فلتر DNS، وابعت تنبيه Telegram حقيقي. دي بتقفل أكبر خانة "متجرّبش".
2. **SafeSearch + YouTube Restricted + حد وقت يومي** في فلتر DNS. أرخص ميزات وأكتر حاجة صاحب بيت أو مدرسة هيسأل عليها.
3. **استهلاك النت لكل جهاز + speed test مجدول.** ممكن يتعملوا من الراوتر لو التعريف بيرجّع bytes، أو من الـ Sensor.
4. **تحديث البرامج الخارجية على الويندوز** (winget upgrade مجدول بموافقات).
5. **موقع الموبايل + Lost mode + Kiosk.**
6. **توقيع كود حقيقي وخادم تحديثات**، قبل ما توزّع البرنامج على أي حد بره البيت.
7. الباقي: syslog وtraps وقوالب SNMP وصفحة الحالة وتقارير PDF.
